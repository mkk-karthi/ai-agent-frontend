# Always Ask Clarification on Doubt

- **Never make unilateral assumptions**: If any user requirement, architecture decision, design choice, or implementation approach is ambiguous or uncertain, do **NOT** decide or proceed on your own.
- **Ask the user first**: Immediately ask the user for clarification before modifying code, adding dependencies, or making architectural assumptions.
- **Prioritize user alignment**: Present clear choices or trade-offs when asking so the user can make an informed decision.
